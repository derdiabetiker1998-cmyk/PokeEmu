# iOS build setup — status and Mac-side instructions

Written entirely on Windows, without any access to a Mac, Xcode, or CocoaPods.
Nothing in this document past "generate `ios/`" has been run or verified —
treat it as a strong starting point, not a working build. Expect to debug it
the same way the Android native build was debugged: read the real
`pod install` / Xcode build error, fix the specific thing it names, repeat.

## What's already true and doesn't need re-deriving

- `ios-pending/PokeEmu/*.swift`, `*.m` — the native module source (JNI-equivalent
  Swift/Obj-C bridge to mGBA). Written and reasoned about carefully, but never
  compiled.
- `ios-pending/mgba-ios/CMakeLists.txt` and `ios-pending/mgba.podspec` — a
  first attempt at building `vendor/mgba` as an iOS static library and
  exposing it as the `mgba` Swift module `MGBABridge.swift` imports. This
  didn't exist before this session — `import mgba` had nothing backing it.
  See the podspec's own comments for the specific risk points to check first.
- `eas.json`'s `development-simulator` profile — builds an unsigned iOS
  Simulator `.app` via EAS's cloud macOS workers. No Apple Developer account
  needed at all for this profile.
- Android's equivalent CMake build is real and green (see git history from
  2026-08-28) — the mGBA-for-iOS approach here deliberately reuses the same
  `EXCLUDE_FROM_ALL` + `target_compile_definitions` pattern that worked there.

## Why this needs a Mac (or Linux) at all

`npx expo prebuild --platform ios` refuses to run on Windows outright (hard
platform check, confirmed by actually trying it — not just a CocoaPods gap).
Once `ios/` exists and is committed to git — the same way `android/` already
is — all *subsequent* builds go through EAS's cloud macOS workers and need no
local Mac at all. The Mac is only needed for this one-time generation step
(and later, for anything that requires actually looking at a running iOS
Simulator, or installing/trusting a build on a physical device).

## Steps to run once real Mac/Linux access exists

Run all of this from the repo root.

### 1. Generate the Xcode project

```bash
npm install
npx expo prebuild --platform ios
```

This creates `ios/PokeEmu.xcodeproj` (or `.xcworkspace` after pod install),
`ios/PokeEmu/AppDelegate.*`, `Info.plist`, a `Podfile`, and a bridging header
(likely `ios/PokeEmu/PokeEmu-Bridging-Header.h`).

### 2. Move the staged native files in

```bash
cp ios-pending/PokeEmu/*.swift ios-pending/PokeEmu/*.m ios/PokeEmu/
cp -r ios-pending/mgba-ios ios/
cp ios-pending/mgba.podspec ios/
```

Files being moved: `MGBABridge.swift`, `GBAKeyMask.swift`,
`PokeEmuCoreModule.swift`, `PokeEmuCoreModule.m`, `PokeEmuRenderView.swift`,
`PokeEmuRenderViewManager.swift`, `PokeEmuRenderViewManager.m`.

### 3. Add the files to the Xcode project target

Open `ios/PokeEmu.xcworkspace` (after step 5) or `.xcodeproj` in Xcode:
right-click the `PokeEmu` group → **Add Files to "PokeEmu"...** → select the
7 files copied in step 2 → make sure **PokeEmu** target membership is checked.
Doing this in Xcode itself (rather than hand-editing `project.pbxproj`) is
deliberate — Xcode's own dialog can't produce a malformed project file the
way a scripted edit risked.

### 4. Add the bridging header import

`PokeEmuCoreModule.swift` subclasses `RCTEventEmitter`, which needs an
Objective-C import made visible to Swift. Open the generated
`ios/PokeEmu/PokeEmu-Bridging-Header.h` (name may differ slightly — check
Build Settings → Swift Compiler → Objective-C Bridging Header for the exact
path) and add:

```objc
#import <React/RCTEventEmitter.h>
```

### 5. Wire the mgba pod into the Podfile

Open `ios/Podfile` and add, near the other pod declarations inside the
`PokeEmu` target block:

```ruby
pod 'mgba', :path => './mgba.podspec'
```

### 6. Install pods

```bash
cd ios && pod install && cd ..
```

This is where `ios-pending/mgba.podspec`'s `prepare_command` actually runs
CMake for the first time. **This is the most likely place to hit a real
error** — see the podspec's own comments for the specific things to check
(output path naming, generated headers, simulator architecture). Fix
whatever the actual `cmake`/`xcodebuild` error says, the same way each
Android CMake error got fixed by reading the real compiler output rather
than guessing further from here.

### 7. Commit `ios/` to git

```bash
git add ios/ ios-pending/  # remove ios-pending/ once its contents are confirmed migrated
git commit -m "feat: generate iOS Xcode project and wire up the mGBA/native bridge"
```

From here on, `ios/` is hand-maintained and git-tracked exactly like
`android/` already is — not regenerated by `prebuild` on every build.

### 8. Verify with the account-free simulator build

Can be run from this Windows machine, or from the Mac — no Apple account
needed:

```bash
npx eas build --profile development-simulator --platform ios --non-interactive
```

Read the build logs the same way the Android debugging in this session did
(`eas build:view <id> --json` → `logFiles[0]` → fetch that signed URL
immediately, since it expires in 15 minutes → the JSON log has a `phase`
field per line, filter to the failing one). Fix what it actually says is
wrong, one real error at a time.

### 9. Once ready for a real device / TestFlight

Needs an Apple Developer account (free tier works for ad-hoc device installs
signed via Xcode directly; the $99/year Program is required for any
TestFlight distribution, internal or external). Not attempted yet — revisit
once an account exists.
